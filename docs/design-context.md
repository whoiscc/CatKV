# CatKV 项目上下文

本文区分项目要达到的结果、实现时遵守的约束、已约定的架构边界、尚待验证的设计提案和当前实现状态。
开发环境的操作说明见[开发环境与首次配置](development.md)。

## 项目目标

- 构建一个兴趣性质的分布式通用键值存储。
- 持续公开运行，允许公众施加实际负载，公开性能、故障、恢复和扩容过程。
- 支持高可用和水平扩容。
- 实践源码与二进制版本管理、容器部署、滚动升级、失败重启以及监控。

这些目标描述预期结果，不规定组件划分或内部实现；具体的验收口径仍需后续确定。

## 实现与部署约束

- 从头实现单机存储引擎和核心分布式协议，不以 RocksDB 等现成存储系统或现成复制协议替代。
- 实现直观流畅优先，性能其次；不为假设中的未来需求提前引入抽象。
- 实际部署要求 KV 节点位于独立物理宿主机。单台开发机上的多个容器仅能模拟逻辑节点，不能验证该物理故障域要求。

## 已约定的架构边界

以下约定指导后续实现，不代表对应组件已经存在。

- 通过分片实现水平扩容。
- Storage 只认识 bytes key → bytes value，不理解名字空间；Gateway 对公众提供名字空间、鉴权、限流和键编码。
- Gateway 没有必须从单个实例恢复的持久化业务状态。需要持久化的配置保存在 Storage，Gateway 缓存配置。
- 通常请求路径的鉴权和限流在网关本地完成，不为每次请求增加额外后端存储访问。

## 起步方案（设计提案）

单机设计以 Rust / Linux 本地文件系统为基础，本开发环境据此准备。
计划先实现单机引擎，再逐步接入网关、复制和分片。单机引擎的起步提案如下，
具体方案需要在实现与验收时验证：

1. 一个追加数据文件、内存哈希索引、独占状态的存储线程。
2. 基本 Get / Put / Delete，区分不存在与空 value；记录格式显式编码并校验 CRC。
3. 成功确认前完成持久化；重启顺序恢复；无法解释的完整记录损坏应报告错误。
4. 初期采用暂停式全量压缩，处理文件同步、原子替换和目录同步。
5. 后续可考虑 group commit，再讨论并发读取和在线压缩。

## 待定事项

- 目标验收：高可用、水平扩容和公开运行的具体验收口径。
- 协议与接口：复制的一致性模型与算法、传输协议、网关元数据所需的原子接口。
- 分片与部署：分片放置与迁移方案、云厂商、最终节点规模。

## 当前实现状态

当前仓库仅包含开发环境和 Rust workspace 骨架，`catkv-storage` 是可构建的空库。
单机存储引擎、网关、复制、分片和公开服务均尚未实现，也没有业务测试。
开发环境检查只验证相关操作在当前环境中可运行，不证明存储持久化或分布式正确性。
